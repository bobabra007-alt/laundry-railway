# Laundra — обновление доходов и рабочих экранов

## Для уже запущенной CRM

1. В существующем GitHub-репозитории загрузите **всё содержимое** этого архива через Add file → Upload files. Сохраните изменения в main. Не загружайте ZIP как файл и не добавляйте внешнюю папку поверх проекта.
2. В Railway оставьте Start Command `npm start`. Базу, DATABASE_URL, AUTH_SECRET и ADMIN_PASSWORD не меняйте.
3. Дождитесь нового Deploy. Миграция добавит архив, доли и регламенты. Перед запуском автоматически исправятся старые начисления и выполнятся проверки четырёх долей.
4. В Deploy Logs найдите `Employee shares verified: fixed split between four people.` Обновите CRM.

База и старые платежи сохраняются. Коррекция старого деления прибыли пишет дополнительные записи в ledger, не стирая оригиналы. Например, прежние 125 USDT одному сотруднику будут скорректированы до 31,25; 93,75 остаются зарезервированными для остальных трёх. Назначение этих долей выполняется при создании остальных участников банка и при старте приложения.

## Что изменилось

- Постоянное деление 25% прибыли на четверых; личный заработок и остаток к выплате показаны отдельно.
- Поиск клиента/партнёра по имени или Telegram, ввод нового имени с созданием справочника при сохранении сделки. Нового клиента получает автор сделки. Права создания проверяются сервером.
- Статусы: Новая, В работе, Ожидает, Завершена, Отменена, Спор; изменение в списке и карточке.
- Повторное открытие завершённой сделки и её удаление доступны администратору и отменяют начисления. Смена статуса назад в Завершена восстанавливает их ровно один раз.
- Удаление помещает сделку в архив; восстановление доступно администратору. Фактические платежи и подтверждённые выплаты не отменяются. Если уже выплаченные деньги превышают исправленный заработок, баланс может быть отрицательным — это сохранённый факт выплаты.
- Два блока платежей: получение от партнёра / выплата клиенту, дата, сумма, остаток и история.
- Общие регламенты: карточки или список, поиск, заголовок, краткое описание, полный текст. Создаёт каждый; редактирует и удаляет автор либо администратор. Редакции сохраняются.

Доли округляются до центов так, чтобы сумма четырёх долей точно совпадала с общими 25%; разница между людьми может составлять 0,01 USDT. У банка максимум четыре активных участника. Дополнительные пользователи могут существовать без участия в распределении.

## Проверка обновления

Проверены production-сборка и TypeScript. Пять автоматических регрессионных тестов покрывают 75/25, точное округление, коррекцию старого начисления, повторное начисление/отмену/восстановление и сохранение фактических выплат. Тесты ledger используют изолированные заглушки; интеграция с вашей Railway-базой проверяется после деплоя.

## Запуск через браузер

1. Создайте приватный репозиторий GitHub `laundra-railway` и загрузите всё содержимое распакованного архива в корень. Не загружайте сам ZIP.
2. В Railway создайте Empty Project. Добавьте Database → PostgreSQL.
3. В том же проекте добавьте GitHub Repo → ваш репозиторий.
4. В Variables **сервиса приложения** добавьте:
   - `DATABASE_URL`: Reference Variable → сервис PostgreSQL → DATABASE_URL;
   - `AUTH_SECRET`: случайный секрет от 32 символов (генератор в START-HERE.html);
   - `ADMIN_PASSWORD`: ваш пароль администратора — минимум 12 символов, максимум 72 байта UTF-8.
5. Примените переменные через Deploy. Дождитесь успешного запуска. В Settings → Networking нажмите Generate Domain.
6. Вход: логин `admin`, ваш ADMIN_PASSWORD. Сотрудников создавайте в разделе Пользователи; права назначаются галочками.

Vercel, Neon и ChatGPT для входа в CRM не нужны.

## Что настроено автоматически

Railway определяет Node.js 24, `npm run build` и `npm start` из package.json. Сборка генерирует Prisma Client и собирает Next.js; к базе на этапе сборки не подключается. Старт последовательно проверяет переменные, применяет миграции, создаёт первого администратора и запускает сервер на `0.0.0.0` с портом Railway PORT.

Повторные миграции и seed сохраняют существующие данные и пароль. Изменение ADMIN_PASSWORD в Railway не сбрасывает пароль существующего администратора. Пароль меняется внутри CRM → Мой профиль.

Приложение и PostgreSQL должны находиться в одном Railway-проекте и environment. Используйте отдельную базу для тестовых окружений. Не переносите production DATABASE_URL в тестовое окружение.

## Вложения

Файлы до 2 МБ хранятся как BYTEA в PostgreSQL, без внешнего хранилища. Загрузка проверяет право редактирования карточки. Скачивание доступно активным вошедшим пользователям (по правилу «все видят всё»). Файлы отдаются как скачиваемые, без публичных ссылок. Объём файлов увеличивает размер базы.

Ранее загруженные файлы в Vercel Blob автоматически не переносятся. Эта версия рассчитана на новый запуск; при использовании существующей базы прежние записи сохраняются, но их файлы надо переносить отдельно.

## Проверка

Проверены сборка Next.js, TypeScript, страница входа, отказ в доступе к вложениям без авторизации и последовательность запуска с изолированными заглушками. Миграции и первый вход на вашей реальной Railway-базе ещё нужно проверить после деплоя. Финансовые сценарии проверяйте на тестовых сделках до реального учёта.

## Для разработчика

```bash
npm ci
cp .env.example .env
npm run build
npm start
```

Без настроенной базы используйте только `npm run build`. `npm start` применяет миграции и seed, поэтому требует DATABASE_URL, AUTH_SECRET и ADMIN_PASSWORD. Для локальной разработки после подготовки базы можно использовать `npm run dev`.
