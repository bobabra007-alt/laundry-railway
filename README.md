# Laundra — запуск без редактирования кода

Откройте **START-HERE.html** двойным щелчком. Это пошаговая инструкция для Windows; установка программ и команды не нужны.

## Самый простой запуск

1. Создайте приватный репозиторий GitHub и загрузите в него **всё содержимое** распакованной папки (не ZIP и не внешнюю папку).
2. Создайте проект Neon. В Connect выключите Connection pooling и скопируйте строку PostgreSQL.
3. В Vercel импортируйте репозиторий и добавьте три Production Environment Variables:
   - `DATABASE_URL`: прямая строка подключения Neon.
   - `AUTH_SECRET`: случайный секрет от 32 символов; генератор находится в START-HERE.html.
   - `ADMIN_PASSWORD`: ваш первый пароль администратора от 12 до 72 символов.
4. Нажмите Deploy. Код уже задаёт сборку и Node.js 24. Для production автоматически выполняются Prisma generate, migrate deploy, seed, затем Next.js build.
5. Откройте production-адрес. Логин — `admin`, пароль — заданный ADMIN_PASSWORD. Создайте сотрудников в разделе Пользователи.

Вход через обычный логин и пароль. Аккаунты ChatGPT сотрудникам не нужны.

## Повторный деплой

Миграции применяются только при Production-деплое (`VERCEL_ENV=production`). Preview и локальная сборка не меняют схему и не создают администратора. Повторный seed не меняет существующий пароль администратора. Менять свой пароль можно в разделе Мой профиль; изменение ADMIN_PASSWORD в Vercel не сбрасывает пароль в базе.

Используйте отдельную базу для Preview/Development, если хотите тестировать с данными. Для первого запуска достаточно Production. Не подключайте тестовые деплои к рабочей базе без необходимости.

DIRECT_URL необязателен. Если DATABASE_URL использует pooler, задайте DIRECT_URL как прямое подключение к той же базе. Для простого запуска инструкция использует одну прямую строку DATABASE_URL.

## Вложения

Необязательны для запуска CRM. Подключите private Vercel Blob, добавьте BLOB_READ_WRITE_TOKEN и сделайте Redeploy. Лимит — 2 МБ. Загрузка реализована; скачивание приватных файлов ещё требует доработки.

## Разработчику

```bash
npm ci
cp .env.example .env
npm run db:generate
npm run db:deploy
npm run db:seed
npm run dev
```

`npm run build` проверяет приложение без миграции БД. На Vercel используется `scripts/vercel-build.mjs`, заданный в `vercel.json`.

## Проверка и ограничения

Production-сборка и TypeScript проверяются перед передачей архива. Без доступа к реальной базе пользователя нельзя подтвердить миграции и первый вход на Vercel. Финансовые операции, права и выплаты нужно проверить на тестовых данных перед реальным использованием.

Не публикуйте .env или секреты. Не создавайте общедоступные ссылки на вложения клиентов.
