# Личная рабочая таблица Laundra
Точка входа — «Моя таблица» (/workspace). Код подготовлен на основе d71421f.
Сотрудник видит свои активные (не архивные) записи всех статусов и свои черновики.
Доступ к изменениям определяется правами на создание или редактирование сделок.
Редактирование ячейки начинается по нажатию, для полного набора полей есть «Изменить».
Порядок и скрытие колонок сохраняются в этом браузере для текущего пользователя.

## Excel
Импортируется первый лист .xlsx, заголовки находятся в первой строке. Лимиты: 5 МБ,
15 000 строк и 120 колонок. До подтверждения доступен предпросмотр первых 100 строк.
Новые имена колонок можно завести в настройках и сопоставить при импорте.
Первая загрузка неизвестного статуса требует сопоставления или оставляет строку черновиком.
Год неполной даты берётся из календаря Asia/Yekaterinburg. Денежные значения — USDT.
Проценты в обычных числовых ячейках указываются как 90 для 90%, формат Excel «Процентный» также поддерживается.
Прибыль рассчитывается сервером. Текстовое поле «Материал» сохраняет ведущие нули.
При публикации обязательны название, клиент, выбор партнёра (можно явно «Без партнёра»),
сумма, оба процента, дата заказа, статус и обязательные дополнительные поля.
«Материал» и «Дата транзакции» по умолчанию обязательны и видны владельцу.
Владелец может изменить обязательность и видимость этих двух полей и своих колонок.

Тот же исходный файл при повторной загрузке распознаётся по контрольной сумме и номеру строки.
Для обновлений выгрузите таблицу из Laundra и сохраните служебные колонки с ID и версиями.
Изменённый сторонний файл без идентификаторов рассматривается как новый. Устаревшие версии
отклоняются. Импорт сохраняет строки отдельными транзакциями; при ошибке строки остальные
сохраняются, итог показывает ошибки. Частично заполненная новая строка остаётся черновиком.
Для опубликованной сделки неполное изменение отклоняется. Исходная сделка остаётся доступна.

## Проверка отдельно от production
Используйте Node.js 24 и отдельную тестовую PostgreSQL. Миграция 20261102090000_workspace
добавляет две таблицы. Для локальной проверки укажите только тестовый DATABASE_URL,
настройте остальные переменные по .env.example и выполните npm ci, npm run db:generate,
npm run db:deploy, npm run db:seed, npm run dev. Тесты: npm test и npm run test:integration.
Для импорта старых клиентских имён проверяются права сотрудника и закрепление клиента.
В общих «Сделках» доступна существующая ручная форма.
